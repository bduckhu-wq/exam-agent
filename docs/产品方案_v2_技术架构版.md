## 一、项目概述

### 1.1 产品定位

面向 K12 教师的**轻量级 AI 智能出题系统 demo**，通过多轮对话梳理出题需求，自动生成结构化试卷并支持预览和导出。

### 1.2 核心价值

- **自然语言交互**：老师用日常语言描述需求，AI 自动提取结构化参数
- **智能参数校验**：AI 主动判断信息是否完整，缺失时追问而非盲目生成
- **多轮对话记忆**：跨轮次保留上下文，无需重复说明已提供的信息
- **一键组卷**：参数确认后自动生成题目数组，按试卷格式排版展示
- **灵活调整**：支持对生成结果的增删改、拖拽排序、重新生成

### 1.3 技术基础

| 项目 | 选型 | 说明 |
|------|------|------|
| 后端框架 | FastAPI | 高性能 Python Web 框架，支持异步和 SSE 流式 |
| Agent 编排 | LangGraph | 把 AI 的"思考+行动"做成流程图，节点=执行步骤，边=流转逻辑 |
| 业务规则层 | Markdown Skill | 把出题规则写成 Markdown 文件，教研可自行修改，无需工程师介入 |
| 会话管理 | SessionMemory | 基于 JSON 文件的持久化，按 session_id 隔离多轮对话上下文 |
| 治理层 | Harness | 执行日志（logs/）+ 异常重试（指数退避）+ 熔断保护（连续失败 5 次自动熔断） |
| LLM | Kimi K2.5（Moonshot） | 支持 Tool Calling + JSON Mode + 流式输出 |
| 前端框架 | Vue 3 | 基于 vercel/chatbot 二次开发，对接 FastAPI 后端 |
| 部署 | 本地开发优先 | 前后端分离，后端端口 8000，前端端口 3000 |

### 1.5 Demo 范围界定

**包含（MVP）**：
- ✅ 多轮对话梳理出题需求（基于 SessionMemory）

### 2.2 追问流程（参数不满足时）

```
老师: "帮我出一份数学试卷"
  │

  │
  AI: "好的！我来帮您出一份数学试卷。还需要了解几个信息：
       1. 这是几年级的？（如：高一、初二）
       2. 使用哪个版本的教材？（如：人教版、北师大版）
       3. 考试范围是哪些章节？
       您可以一起告诉我，也可以我们逐个确认。"
  │
老师: "高一的，人教版，范围是必修一第三章函数"
  │
  AI (clarify 节点): 更新参数 → 学科=数学, 年级=高一, 版本=人教版, 范围=必修一第三章函数
      核心四要素满足 ✅，题型由 AI 自主决定

  │
  AI: "收到！根据您的需求，我为您规划如下：
       📚 学科：数学 | 🎓 年级：高一 | 📕 教材：人教版
       📖 范围：必修一 第三章 函数的概念与性质
       📝 题型：选择题(8) + 填空题(4) + 解答题(4) + 证明题(2)
       🎯 难度：3:5:2（单元测验标准梯度）
       📊 题量：18 道 | ⏱ 预计 45 分钟

       您可以在下方确认面板中查看详情，也可以补充其他要求。"
       [参数确认面板在输入框上方展开 →]
```

### 2.3 参数完整性规则

AI 需要校验的**必要参数**：

| 参数 | 是否必须 | 缺失时策略 |
|------|---------|-----------|
| 学科 | ✅ 必须 | 首轮追问 |
| 年级 | ✅ 必须 | 首轮追问 |
| 教材版本 | ✅ 必须 | 与学科/年级关联追问（如"人教版高一数学"） |
| 考试范围（课本章节） | ✅ 必须 | 追问具体到课本章节（如"第三章 函数"） |
| 题型 | 🤖 AI 自主决定 | **不追问**，AI 根据出题场景自动匹配合理题型组合 |
| 难度 | 🤖 AI 自主决定 | **不追问**，AI 根据出题场景推荐合理梯度比例（如课后练习 5:3:2，考试 2:6:2） |
| 题目数量 | 🤖 AI 自主决定 | **不追问**，AI 根据出题场景自动匹配合理题量 |
| 地区 | ❌ 可选 | 不追问，默认"通用" |
| 考试时长 | ❌ 可选 | 不追问，根据题量自动估算 |

**题型自主决定规则**：

AI 根据**学科 + 年级 + 章节 + 出题场景**四个维度综合判断题型组合，完全动态决定，不使用固定映射表。AI 应基于真实教学场景匹配题型。

**判断依据**：
- **学科特性**：不同学科有截然不同的题型体系
  - 数学：选择题、填空题、解答题、证明题、计算题、应用题
  - 语文：选择题、填空题、默写题、文言文翻译、阅读理解、作文题
  - 英语：选择题、完形填空、阅读理解、短文改错、书面表达
  - 物理：选择题、填空题、实验题、计算题、简答题
  - 化学：选择题、填空题、实验探究题、计算题
  - 生物：选择题、填空题、实验题、识图作答题
  - 历史/政治/地理：选择题、材料分析题、简答题、论述题
- **年级差异**：低年级题型偏简单直观（选择、填空、判断），高年级增加复杂题型（证明、综合大题、论述）
- **章节内容**：计算类章节侧重计算题/解答题，概念类章节侧重选择题/判断题，阅读类章节侧重阅读理解
- **出题场景**：课后练习偏基础题型，考试偏全面覆盖，专项训练聚焦特定题型

**示例**：
| 场景 | AI 可能决定的题型 |
|------|-----------------|
| 高一数学·函数·单元测验 | 选择题(8) + 填空题(4) + 解答题(4) + 证明题(2) |
| 初二语文·古诗词·课后练习 | 默写题(5) + 选择题(3) + 简答题(2) |
| 高三英语·阅读理解·专项训练 | 阅读理解(4篇) + 完形填空(1篇) |
| 初三物理·电学·期中考试 | 选择题(10) + 填空题(4) + 实验题(2) + 计算题(3) |

老师可以在参数确认卡片中查看 AI 推荐的题型组合，如有异议可直接在对话中告知 AI 调整。

**题量自主决定规则**：

AI 根据出题场景自动匹配合理题量，无需老师指定。匹配规则如下：

| 出题场景 | AI 推荐题量 | 说明 |
|---------|-----------|------|
| 课后练习 | 8-12 道 | 日常作业量，学生 15-20 分钟可完成 |
| 单元测验 | 15-20 道 | 课堂 40-45 分钟测验 |
| 期中考试 | 20-25 道 | 90 分钟标准考试 |
| 期末考试 | 25-30 道 | 120 分钟标准考试 |
| 专项训练 | 10-15 道 | 针对性强化练习 |

**难度梯度规则**：

难度以**比例**表示（简单:中等:困难），AI 根据出题场景和真实教学规律推荐合理比例：

| 出题场景 | AI 推荐难度比例 | 真实教学依据 |
|---------|---------------|------------|
| 课后练习 | 5:3:2 | 以基础题为主，确保学生能独立完成大部分题目，建立信心 |
| 单元测验 | 3:5:2 | 兼顾基础巩固与能力区分，中等题占比最高 |
| 期中/期末考试 | 2:6:2 | 标准考试梯度，中等题为主体，简单题和困难题作为两端锚点，区分度好 |
| 专项训练 | 2:5:3 | 针对薄弱环节强化，中等和困难题占比更高，有一定挑战性 |
| 拔高/竞赛训练 | 1:4:5 | 高难度为主，选拔性考试梯度 |

**考试范围（课本章节维度）**：

考试范围以**课本章节**为基本粒度，而非零散的知识点标签。AI 需要识别并引导老师确认到章节级别：

```
❌ 模糊：范围 = "函数"
✅ 明确：范围 = "人教版高一数学必修一 第三章 函数的概念与性质"

❌ 模糊：范围 = "力学"
✅ 明确：范围 = "人教版八年级物理下册 第七章 力"
```

当老师描述的范围不够精确时，AI 应追问到具体章节。

**参数满足判定逻辑**：
- 学科 + 年级 + 教材版本 + 考试范围（章节） → **可以生成**（核心四要素满足）
- 题型/题量/难度 → AI 自主决定，不作为必要参数
- AI 在**每轮对话后**评估参数完整度，满足后在输入框上方展开参数确认卡片

### 3.2 前端适配器模式

参考 vercel/chatbot 的 Adapter 模式，前端支持多种后端切换：

```
前端适配器层
├── adapters/
│   ├── base.ts         # 基础接口定义
│   ├── coze.ts         # Coze 适配器（原有）
│   ├── mock-adapter.ts # Mock 适配器（测试用）
│   └── local.ts        # Local 适配器 ← 新增，对接 FastAPI 后端
```

**LocalAdapter 核心接口**：

```typescript
// adapters/local.ts

export interface LocalAdapter {
  // 初始化会话（首次对话时调用，返回 session_id）
  initSession(): Promise<{ sessionId: string }>

  // 发送消息并生成试卷
  generateExam(params: {
    sessionId: string
    userInput: string
    subject?: string
    grade?: string
    textbookVersion?: string
    chapters?: string[]
    questionTypes?: string[]
    difficultyRatio?: string
    totalQuestions?: number
    additionalNotes?: string
  }): Promise<ExamResponse>

  // 流式生成（返回 SSE 事件流）
  generateExamStream(params: {
    sessionId?: string
    userInput: string
    // ... 同上
  }): Promise<EventStream>

  // 追问（分析用户输入，提取/更新参数）
  clarify(params: {
    sessionId: string
    userInput: string
    currentParams: Record<string, any>
  }): Promise<ClarifyResponse>

  // 题目改编
  adaptQuestion(params: {
    sessionId: string
    originalQuestion: Question
    adaptDirection: string
    adaptDetail?: string
  }): Promise<Question>

  // 会话管理
  listSessions(): Promise<Session[]>
  getSession(sessionId: string): Promise<Session>
  deleteSession(sessionId: string): Promise<void>
}
```

**切换后端只需修改配置**：

```typescript

## 四、技术设计

### 4.1 Agent 架构（LangGraph + Markdown Skill）

#### 4.1.1 架构概述

后端采用 **LangGraph** 作为 Agent 编排引擎，核心思路是把 AI 出题流程拆成若干**节点（Node）**，节点之间通过**边（Edge）**连接成有向图。

```
┌──────────────────────────────────────────────────────────────┐
│                        LangGraph 图                          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌─────────┐     ┌─────────┐     ┌─────────┐    ┌─────────┐│
│  │ clarify │────▶│ analyze │────▶│  plan   │───▶│generate ││
│  │ (追问)   │     │ (分析)   │     │ (蓝图)   │    │ (生成)   ││
│  └────┬────┘     └─────────┘     └─────────┘    └────┬────┘│
│       │                                               │       │
│       │  ◀───────── 循环追问 ◀───────────── 参数不满足 ─│       │
│       │                                               │       │
│       │                                               ▼       │
│       │                                        ┌─────────┐   │
│       │                                        │validate │   │
│       │                                        │ (验证)   │   │
│       │                                        └────┬────┘   │
│       │                                             │       │
│       ◀─────────────── 验证失败则重新生成 ◀──────────┘       │
└──────────────────────────────────────────────────────────────┘
```

**节点说明**：

| 节点 | 职责 | Skill 支持 |
|------|------|-----------|
| `clarify` | 分析用户输入，提取出题参数；缺失时主动追问 | question-generator.md |
| `analyze` | 知识分析：梳理章节核心知识点和前置知识 | question-generator.md |
| `plan` | 设计蓝图：确定题型组合、题量、难度梯度 | question-generator.md |
| `generate` | 逐题生成：按蓝图生成每道题 | question-generator.md |
| `validate` | 质量验证：检查题量、知识点覆盖、答案准确性 | question-generator.md |

#### 4.1.2 Markdown Skill 层

每个节点执行时，通过 **SkillManager** 加载对应的 Markdown Skill 文件，将 Skill 内容作为 **System Prompt 的一部分**注入 LLM。

```
节点执行流程：
  1. SkillManager 读取 question-generator.md
  2. 将 Skill 内容拼接到 System Prompt
  3. 调用 LLM（Kimi K2.5）
  4. 解析 LLM 返回，更新图状态
  5. 根据边的条件决定下一步走哪个节点
```

**question-generator.md 结构**：

```markdown
---
name: question-generator
description: 根据学科、年级、章节生成高质量试卷题目
triggerHint: 出题,组卷,生成试卷,出一份试卷,自动出题
workflow:
  nodes:
    - id: analyze
      name: 知识分析
      description: 分析章节核心知识点和前置知识
    - id: plan
      name: 设计蓝图
      description: 设计题目结构、题型组合、难度梯度
    - id: generate
      name: 逐题生成
      description: 根据蓝图逐题生成
    - id: validate
      name: 质量验证
      description: 验证题目质量和答案准确性
  edges:
    - from: analyze
      to: plan
    - from: plan
      to: generate
    - from: generate
      to: validate
  entry: analyze
---

# Question Generator

[出题规则的完整描述，包括：题型枚举、难度规则、题量规则、输出格式等]
```

**Skill 优势**：
- 教研老师可以直接编辑 Markdown 文件来调整出题规则，无需改代码
- 不同学科可以有各自专属的 Skill 文件（如 question-generator-math.md）
- Skill 支持热更新，修改后通过 `POST /api/skills/reload` 无需重启服务

#### 4.1.3 会话状态管理（SessionMemory）

多轮对话通过 **SessionMemory** 持久化，基于 JSON 文件存储：

```
sessions/
├── {session_id_1}.json   # 会话1的完整上下文
├── {session_id_2}.json   # 会话2的完整上下文
└── ...
```

**Session 文件结构**：

```json
{
  "session_id": "a1b2c3d4-...",
  "created_at": "2026-04-22T10:00:00Z",
  "updated_at": "2026-04-22T10:05:00Z",
  "messages": [
    { "role": "user", "content": "帮我出一份数学试卷" },
    { "role": "assistant", "content": "请问是几年级的？" },
    { "role": "user", "content": "高一的" }
  ],
  "params": {
    "subject": "数学",
    "grade": "高一",
    "textbook_version": null,
    "chapters": [],
    "question_types": null,
    "difficulty_ratio": null,
    "total_questions": null,
    "additional_notes": ""
  },
  "context": {
    "current_skill": "question-generator",
    "current_node": "clarify",
    "history_nodes": ["clarify"]
  }

```

**会话流程**：

```
首次请求（无 session_id）
  → 生成新 session_id
  → 创建 sessions/{id}.json
  → clarify 节点执行，记录消息和 params
  → 返回 response（含 session_id）

后续请求（带 session_id）
  → 读取 sessions/{id}.json
  → 加载历史 messages + params 到图状态
  → 从上次断点继续执行
  → 更新 sessions/{id}.json
  → 返回 response
```

### 4.2 Lead Agent（主调度）

**Lead Agent** 是 LangGraph 图的入口，负责接收用户输入、协调各节点执行、管理会话状态。

```python
# agent/lead.py 核心逻辑（简化版）

### 4.5 题型动态决定规则

AI 根据**学科 + 年级 + 章节 + 出题场景**四个维度综合判断题型组合：

| 维度 | 判断逻辑 |
|------|---------|
| 学科 | 不同学科有截然不同的题型体系（数学有证明题，语文有默写题，物理有实验题） |
| 年级 | 低年级偏基础题型，高年级增加复杂题型（证明、综合大题） |
| 章节 | 计算类章节侧重解答题，概念类章节侧重选择题 |
| 场景 | 课后练习偏基础，考试偏全面，专项训练聚焦特定题型 |

**各学科推荐题型组合**：

| 学科 | 推荐题型组合 |
|------|------------|
| 数学 | choice + fill_blank + short_answer + proof |
| 语文 | choice + recitation + reading + essay |
| 英语 | choice + cloze + reading + writing |
| 物理 | choice + fill_blank + experiment + calculation |
| 化学 | choice + fill_blank + experiment + calculation |
| 生物 | choice + fill_blank + experiment + diagram |
| 历史/政治/地理 | choice + material_analysis + short_answer |

#### 4.6.2 异常重试

LLM 调用失败时自动重试，采用**指数退避**策略：

```
第1次失败 → 等 1s → 重试
第2次失败 → 等 2s → 重试
第3次失败 → 等 4s → 重试 → 仍失败则返回错误
```

#### 4.6.3 熔断保护（CircuitBreaker）

当 LLM 连续失败 5 次，触发熔断：
- 后续请求直接返回 503，不再调用 LLM
- 60 秒后自动进入"半开"状态，允许 1 次尝试
- 成功则关闭熔断，失败则继续熔断 60 秒

手动重置：
```bash
curl -X POST http://localhost:8000/api/circuit-breaker/reset
```

### 4.7 前端 LocalAdapter 实现

```typescript
// adapters/local.ts

const API_BASE = 'http://localhost:8000'

export class LocalAdapter {
  private sessionId: string | null = null

  async generateExam(params: {
    userInput: string
    subject?: string
    grade?: string
    textbookVersion?: string
    chapters?: string[]
    questionTypes?: string[]
    difficultyRatio?: string
    totalQuestions?: number
    additionalNotes?: string
  }): Promise<ExamResponse> {
    const response = await fetch(`${API_BASE}/api/exam/generate`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        session_id: this.sessionId,
        ...params,
      }),
    })

    const result = await response.json()

    // 保存 session_id 用于后续请求
    if (result.session_id) {
      this.sessionId = result.session_id
    }

    return result
  }

  async *generateExamStream(params: {
    userInput: string
    subject?: string
    grade?: string
    // ...
  }): AsyncGenerator<StreamEvent> {
    const response = await fetch(`${API_BASE}/api/exam/generate/stream`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        session_id: this.sessionId,
        ...params,
      }),
    })

    const reader = response.body.getReader()
    const decoder = new TextDecoder()

    while (true) {
      const { done, value } = await reader.read()
      if (done) break

      const text = decoder.decode(value)
      const lines = text.split('\n')

      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const data = JSON.parse(line.slice(6))
          yield data
        }
      }
    }
  }

  async clarify(userInput: string, currentParams: Record<string, any>): Promise<ClarifyResponse> {
    const response = await fetch(`${API_BASE}/api/exam/clarify`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        session_id: this.sessionId,
        user_input: userInput,
        current_params: currentParams,
      }),
    })
    return response.json()
  }

  async adaptQuestion(
    originalQuestion: Question,
    adaptDirection: string,
    adaptDetail?: string
  ): Promise<Question> {
    const response = await fetch(`${API_BASE}/api/exam/adapt`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        session_id: this.sessionId,
        original_question: originalQuestion,
        adapt_direction: adaptDirection,
        adapt_detail: adaptDetail,
      }),
    })
    const result = await response.json()
    return result.data
  }
}

## 七、技术决策

### 7.1 为什么用 FastAPI + LangGraph

| 维度 | 说明 |
|------|------|
| **工程成熟度** | FastAPI 是 Python 生產級 Web 框架，LangGraph 是 LangChain 官方出品，社区活跃 |
| **多轮对话** | LangGraph 的图状态自动在节点间传递，对话上下文管理天然 |
| **Markdown Skill** | 业务规则和代码分离，教研可自行修改 Skill 文件 |
| **可观测性** | Harness 层（日志+熔断）让线上问题可追踪 |
| **前后端分离** | 前端专注 UI，后端专注 AI 逻辑，通过 HTTP 接口解耦 |

### 7.2 为什么用 Markdown Skill

**核心优势：业务规则可编辑，无需工程介入**

```markdown
# question-generator.md

## 题型枚举
- choice：选择题
- fill_blank：填空题
...

## 难度梯度规则
- 课后练习：5:3:2
- 单元测验：3:5:2
...

## 输出格式
```json
{
  "title": "...",
  "questions": [...]
}
```
```

教研老师修改 Markdown 文件 → 调用 `POST /api/skills/reload` → 规则立即生效，无需重启服务。

### 7.3 为什么不用 DeerFlow 的完整架构

| DeerFlow 组件 | 决策 | 原因 |
|--------------|------|------|
| LangGraph 编排 | ✅ 用 | 核心需求，完全一致 |
| Markdown Skill | ✅ 用 | 核心需求，完全一致 |
| SandBox 沙箱 | ❌ 不用 | 出题场景不需要代码执行 |
| Sub-Agent 分工 | ❌ 不用 | 单 Agent 足够，出题流程不复杂 |
| DeerFlow 前端 | ❌ 不用 | 已有 Vue 前端 |
| 多容器部署 | ❌ 不用 | 单 Python 进程即可，简化部署 |

### 7.4 模型选择

| 项目 | 选型 | 说明 |
|------|------|------|
| **模型** | Kimi K2.5 | Moonshot 出品，中文能力强，支持 Tool Calling |
| **SDK** | LangChain / raw HTTP | 直接调用 Moonshot OpenAI 兼容接口 |
| **API Base** | `https://api.moonshot.cn/v1` | 官方接口 |
| **环境变量** | `MOONSHOT_API_KEY` | 本地配置，不在代码中硬编码 |

### 7.5 数学公式渲染

试卷中数学公式使用 **KaTeX**（前端已有）或 **Unicode Math** 降级渲染。

### 7.6 拖拽排序

使用 **@dnd-kit/core**（React 生态主流，轻量）。

### 7.7 Word 导出

使用 **python-docx**（后端生成）+ `aiohttp` 流式返回，前端直接下载。

## 十、风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| AI 生成题目质量不稳定 | 题目可能有错误或不合理 | 生成后校验 + 老师可逐题替换/重新生成 |
| JSON 输出格式不稳定 | 解析失败 | 后端 Skill Prompt 强调 JSON 格式 + 重试机制 |
| 多轮对话 token 膨胀 | 对话轮次多了之后 LLM 调用变慢 | SessionMemory 自动管理上下文长度 |
| LLM 持续失败 | 服务不可用 | CircuitBreaker 熔断保护 + 日志追踪 |
| 数学公式渲染 | 复杂公式可能渲染异常 | 降级到 Unicode 或纯文本 |
| 前端 Vue 对接 | 流式接口需要 EventSource 处理 | LocalAdapter 已封装 stream 逻辑 |
